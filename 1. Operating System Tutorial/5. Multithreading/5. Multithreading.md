# Multithreading trong Hệ điều hành

## Khái niệm cơ bản về Thread

### Thread là gì?

Thread (luồng) là đơn vị cơ bản của việc sử dụng CPU. Một thread bao gồm một thread ID, program counter, một tập register, và stack. Nó chia sẻ với các thread khác cùng process mã lệnh, dữ liệu và các tài nguyên hệ thống như file mở và tín hiệu.

### So sánh Thread và Process

| Đặc điểm | Thread | Process |
|----------|--------|---------|
| Định nghĩa | Đơn vị thực thi nhỏ nhất | Chương trình đang thực thi |
| Tài nguyên | Chia sẻ mã lệnh, dữ liệu và tài nguyên | Tài nguyên độc lập |
| Không gian bộ nhớ | Dùng chung không gian địa chỉ | Không gian địa chỉ riêng biệt |
| Giao tiếp | Giao tiếp dễ dàng qua bộ nhớ chia sẻ | Cần cơ chế IPC phức tạp hơn |
| Chuyển đổi ngữ cảnh | Nhanh hơn | Chậm hơn |
| Tính ổn định | Nếu một thread gặp lỗi, có thể ảnh hưởng đến các thread khác | Các process độc lập với nhau |
| Tạo mới | Nhẹ hơn, tốn ít tài nguyên | Nặng hơn, tốn nhiều tài nguyên |

## Lợi ích của Multithreading

1. **Đáp ứng cao (Responsiveness)**: Ứng dụng vẫn có thể phản hồi người dùng trong khi xử lý các tác vụ khác ở background.

2. **Chia sẻ tài nguyên (Resource sharing)**: Các thread chia sẻ bộ nhớ và tài nguyên của process, giúp tiết kiệm và sử dụng hiệu quả tài nguyên.

3. **Kinh tế (Economy)**: Tạo và chuyển đổi ngữ cảnh giữa các thread ít tốn kém hơn so với process.

4. **Tận dụng kiến trúc đa xử lý (Multiprocessor utilization)**: Các thread có thể chạy song song trên các bộ xử lý khác nhau, tăng hiệu suất.

5. **Cải thiện hiệu suất (Performance improvement)**: Có thể chia nhỏ các tác vụ thành nhiều thread xử lý đồng thời.

## Mô hình Multithreading

### 1. Many-to-One Model (Nhiều-Một)

- Nhiều user-level thread ánh xạ tới một kernel thread
- **Ưu điểm**: Quản lý thread hiệu quả, không cần hỗ trợ từ kernel
- **Nhược điểm**: Nếu một user thread thực hiện lệnh blocking, toàn bộ process bị block
- **Ví dụ**: Solaris Green Threads, GNU Portable Threads

### 2. One-to-One Model (Một-Một)

- Mỗi user thread tương ứng với một kernel thread
- **Ưu điểm**: Chạy song song tốt hơn, một thread bị block không ảnh hưởng đến thread khác
- **Nhược điểm**: Tạo thread mới tốn kém, số lượng thread bị giới hạn bởi hệ thống
- **Ví dụ**: Windows NT/2000/XP, Linux, Solaris 9 trở lên

### 3. Many-to-Many Model (Nhiều-Nhiều)

- Nhiều user thread ánh xạ tới số lượng kernel thread nhỏ hơn hoặc bằng
- **Ưu điểm**: Kết hợp ưu điểm của hai mô hình trên
- **Nhược điểm**: Phức tạp trong triển khai
- **Ví dụ**: Solaris (phiên bản cũ), Windows NT/2000 với ThreadFiber package

### 4. Two-level Model (Mô hình hai cấp)

- Kết hợp Many-to-Many với One-to-One
- Cho phép ứng dụng sử dụng các thread kernel cụ thể khi cần thiết
- **Ví dụ**: IRIX, HP-UX, Tru64 UNIX

## Thư viện Thread

### POSIX Threads (Pthreads)

Pthreads là một tiêu chuẩn IEEE để lập trình đa luồng, định nghĩa API cho quản lý thread.

```c
#include <pthread.h>

void *thread_function(void *arg) {
    // Mã lệnh của thread
    pthread_exit(NULL);
}

int main() {
    pthread_t thread_id;
    pthread_create(&thread_id, NULL, thread_function, NULL);
    pthread_join(thread_id, NULL);
    return 0;
}
```

### Java Threads

Java cung cấp hỗ trợ đa luồng tích hợp thông qua lớp Thread và interface Runnable.

```java
class MyThread extends Thread {
    public void run() {
        // Mã lệnh của thread
    }
}

class MyRunnable implements Runnable {
    public void run() {
        // Mã lệnh của thread
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread thread1 = new MyThread();
        thread1.start();
        
        Thread thread2 = new Thread(new MyRunnable());
        thread2.start();
    }
}
```

### C# Threads

C# cung cấp namespace System.Threading cho lập trình đa luồng.

```csharp
using System;
using System.Threading;

class Program {
    static void ThreadFunction() {
        // Mã lệnh của thread
    }
    
    static void Main() {
        Thread thread = new Thread(ThreadFunction);
        thread.Start();
        thread.Join();
    }
}
```

## Vấn đề phổ biến trong Multithreading

### 1. Race Condition (Tình trạng đua)

Race condition xảy ra khi hai hay nhiều thread cùng truy cập và sửa đổi dữ liệu chia sẻ đồng thời, và kết quả phụ thuộc vào thứ tự thực thi.

```c
// Ví dụ race condition
int counter = 0;

// Thread 1
void increment() {
    counter++; // Đọc, tăng, ghi lại
}

// Thread 2
void increment() {
    counter++; // Đọc, tăng, ghi lại
}

// Nếu hai thread chạy đồng thời, counter có thể không tăng đúng 2 đơn vị
```

### 2. Critical Section (Miền găng)

Critical section là đoạn mã mà trong đó thread truy cập dữ liệu chia sẻ và cần được bảo vệ để tránh race condition.

### 3. Thread Synchronization (Đồng bộ hóa Thread)

#### a. Mutex (Mutual Exclusion)

Mutex là cơ chế đồng bộ hóa cho phép chỉ một thread được thực thi critical section tại một thời điểm. Thread khác muốn vào critical section phải chờ đợi.

```c
// Ví dụ Mutex trong Pthreads
pthread_mutex_t mutex;
pthread_mutex_init(&mutex, NULL);

void safe_increment() {
    pthread_mutex_lock(&mutex);
    counter++; // Critical section
    pthread_mutex_unlock(&mutex);
}
```

#### b. Semaphore

Semaphore là biến đếm được sử dụng để kiểm soát truy cập vào tài nguyên chia sẻ bởi nhiều thread.

```c
// Ví dụ Semaphore trong Pthreads
sem_t semaphore;
sem_init(&semaphore, 0, 1); // Binary semaphore

void safe_increment() {
    sem_wait(&semaphore);
    counter++; // Critical section
    sem_post(&semaphore);
}
```

#### c. Monitor

Monitor là cấu trúc đồng bộ hóa cấp cao hơn, bao gồm mutex và condition variables.

```java
// Ví dụ Monitor trong Java
public class Counter {
    private int count = 0;
    
    public synchronized void increment() {
        count++;
    }
    
    public synchronized int getCount() {
        return count;
    }
}
```

#### d. Condition Variables

Condition variables cho phép thread đợi một điều kiện cụ thể trở thành true trước khi tiếp tục.

```c
// Ví dụ Condition Variable trong Pthreads
pthread_mutex_t mutex;
pthread_cond_t cond;

void consumer() {
    pthread_mutex_lock(&mutex);
    while (buffer_empty) {
        pthread_cond_wait(&cond, &mutex); // Giải phóng mutex và chờ signal
    }
    // Tiêu thụ dữ liệu
    pthread_mutex_unlock(&mutex);
}

void producer() {
    pthread_mutex_lock(&mutex);
    // Sản xuất dữ liệu
    buffer_empty = false;
    pthread_cond_signal(&cond); // Báo hiệu cho consumer
    pthread_mutex_unlock(&mutex);
}
```

### 4. Deadlock trong Multithreading

Deadlock xảy ra khi hai hoặc nhiều thread không thể tiếp tục vì mỗi thread đang giữ tài nguyên và chờ đợi tài nguyên từ thread khác.

#### Ví dụ Deadlock

```c
// Thread 1
pthread_mutex_lock(&mutex1);
pthread_mutex_lock(&mutex2);
// Critical section
pthread_mutex_unlock(&mutex2);
pthread_mutex_unlock(&mutex1);

// Thread 2
pthread_mutex_lock(&mutex2);
pthread_mutex_lock(&mutex1);
// Critical section
pthread_mutex_unlock(&mutex1);
pthread_mutex_unlock(&mutex2);
```

#### Ngăn chặn Deadlock

1. **Tránh lồng khóa**: Hạn chế việc giữ nhiều khóa cùng lúc.
2. **Thứ tự khóa**: Luôn luôn khóa theo cùng một thứ tự.
3. **Timeout**: Sử dụng khóa có timeout.
4. **Phát hiện deadlock**: Triển khai phát hiện và khôi phục deadlock.

### 5. Livelock

Livelock xảy ra khi threads liên tục thay đổi trạng thái để đáp ứng với các thay đổi của thread khác, nhưng không có thread nào thực sự tiến triển.

### 6. Starvation (Đói tài nguyên)

Starvation xảy ra khi một thread không bao giờ được cấp phát tài nguyên cần thiết và không thể tiến triển.

## Mô hình lập trình Thread

### 1. Boss-Worker Model

- Một thread chính (boss) phân chia công việc cho các thread công nhân (workers)
- Thường dùng một hàng đợi task được chia sẻ
- **Ưu điểm**: Phân công công việc đơn giản
- **Nhược điểm**: Boss có thể trở thành bottleneck

### 2. Pipeline Model

- Mỗi thread thực hiện một phần của tác vụ và chuyển kết quả cho thread tiếp theo
- **Ưu điểm**: Chuyên biệt hóa, tận dụng cache
- **Nhược điểm**: Tốc độ bị giới hạn bởi stage chậm nhất

### 3. Peer Model

- Các thread hoạt động độc lập, xử lý các công việc riêng biệt
- **Ưu điểm**: Không có điểm nghẽn
- **Nhược điểm**: Phức tạp trong quản lý

## Thread Pools

Thread pool là một tập hợp các thread được tạo sẵn để xử lý các tác vụ. Thay vì tạo thread mới cho mỗi tác vụ, tác vụ được gửi đến thread pool để xử lý.

### Lợi ích của Thread Pool

1. **Tái sử dụng**: Giảm overhead tạo và hủy thread
2. **Kiểm soát tốt hơn**: Giới hạn số thread đồng thời
3. **Cải thiện hiệu suất**: Tránh tạo quá nhiều thread dẫn đến thrashing

### Ví dụ Thread Pool trong Java

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ThreadPoolExample {
    public static void main(String[] args) {
        // Tạo thread pool với 5 thread
        ExecutorService executor = Executors.newFixedThreadPool(5);
        
        // Gửi tác vụ cho thread pool
        for (int i = 0; i < 10; i++) {
            final int taskId = i;
            executor.execute(() -> {
                System.out.println("Task " + taskId + " đang thực thi bởi " + 
                                   Thread.currentThread().getName());
            });
        }
        
        // Đóng thread pool
        executor.shutdown();
    }
}
```

## Thực tiễn tốt trong lập trình đa luồng

1. **Giảm thiểu dữ liệu chia sẻ**: Hạn chế sử dụng biến toàn cục, ưu tiên truyền thông số.

2. **Immutability**: Sử dụng đối tượng không thay đổi khi có thể.

3. **Đồng bộ hóa hợp lý**: Chỉ khóa khi cần thiết, giảm thiểu kích thước critical section.

4. **Tránh khóa lồng nhau**: Để ngăn ngừa deadlock.

5. **Sử dụng cấu trúc đồng bộ hóa cao cấp**: Ví dụ như ReadWriteLock, ConcurrentHashMap, AtomicInteger thay vì tự triển khai.

6. **Tránh busy waiting**: Sử dụng condition variables thay vì polling.

7. **Xử lý ngoại lệ**: Đảm bảo xử lý ngoại lệ trong mỗi thread.

8. **Sử dụng thread pools**: Tránh tạo và hủy thread thường xuyên.

9. **Test kỹ lưỡng**: Sử dụng công cụ phân tích concurrency và stress testing.

## Các mô hình lập trình đồng thời hiện đại

### 1. Actor Model

- Các "actor" là đơn vị cơ bản, giao tiếp thông qua truyền thông điệp bất đồng bộ
- Mỗi actor có trạng thái riêng, không chia sẻ trực tiếp
- **Ví dụ**: Akka (Java/Scala), Erlang

### 2. Coroutines (Đồng thời có hợp tác)

- Mô hình đồng thời nhẹ hơn thread
- Hỗ trợ suspending và resuming tại các điểm xác định
- **Ví dụ**: Kotlin Coroutines, Python asyncio, Go goroutines

### 3. Reactive Programming

- Dựa trên luồng dữ liệu bất đồng bộ và lan truyền thay đổi
- Thích hợp cho ứng dụng phản hồi nhanh, có tính đàn hồi
- **Ví dụ**: RxJava, RxJS, Reactor

### 4. Concurrent Collections

- Các cấu trúc dữ liệu được thiết kế để an toàn với thread
- Giảm thiểu nhu cầu khóa rõ ràng
- **Ví dụ**: java.util.concurrent package

## Kết luận

Multithreading là một kỹ thuật quan trọng trong lập trình hiện đại, cho phép tận dụng tối đa sức mạnh của hệ thống đa lõi và cải thiện khả năng đáp ứng của ứng dụng. Tuy nhiên, lập trình đa luồng cũng đi kèm với những thách thức như race condition, deadlock, và khó debug. Việc hiểu rõ các nguyên tắc, mô hình, và thực tiễn tốt trong multithreading là rất quan trọng để phát triển ứng dụng hiệu quả và đáng tin cậy.

Các hệ điều hành hiện đại đều cung cấp hỗ trợ mạnh mẽ cho multithreading, và các ngôn ngữ, framework lập trình cũng liên tục phát triển các API và mô hình lập trình đồng thời mới để giúp lập trình viên xử lý các vấn đề phức tạp của multithreading dễ dàng hơn.
